## 후속 수정: 카메라별 독립 번호 압축

앞선 구현은 두 카메라의 관측 목록을 합쳐 영상 번호를 압축했다.
따라서 CAM1에 한 명만 남아도 CAM2에서 보이는 다른 사람이 앞 번호를 차지해 CAM1에 person2가 남을 수 있었다.

영상 번호는 이제 카메라마다 독립적으로 압축한다.

- CAM1에 8·10이 남으면 CAM1은 1·2로 표시한다. CAM2의 다른 사람 목록은 이 번호에 영향을 주지 않는다.
- 각 카메라에 한 명이면 각각 person1이다. 한쪽만 사람이 사라지면 그 카메라만 압축한다.
- 각 카메라의 등장 순서를 기억한다. UNKNOWN으로 바뀌어도 보이는 사람의 순서를 바꾸지 않는다.
- 영상, 관리자 목록, 현재 FrameObservation, 상태 API, 현재 관측 JSON에 카메라별 번호를 동일하게 적용한다.
- 내부 추적 ID와 카메라 매칭·현재 SAFE/DANGER는 유지한다. 서로 다른 사람이 각 화면에서 person1이 되더라도
  표시 번호만으로 판정을 합치지 않는다. 결합 표는 동일인 추적 ID별로 유지한다.
- 결합 API의 `camera_person_ids`에 각 카메라의 현재 번호를 제공한다. 후속 요청으로 표의 추가 번호 표시는 제거했다.
  카메라 셀은 SAFE/DANGER/UNKNOWN만 표시하며 추적·결합 정책은 유지한다.

서로 다른 인원 집합을 보는 두 카메라를 각각 1부터 압축하면 같은 물리적 사람의 표시 번호가 다를 수 있다.
예: CAM1은 A·B → 1·2, CAM2는 B → 1. 이때 B의 공통 추적 연결은 유지한다.
이는 카메라별 번호 압축과 동일인 추적을 구분해야 하는 경우다.

## 원인

이전 구현에서는 공통 Ground 좌표가 0.15m 이상 다르면 순차 등장한 사람도 서로 다른 내부 ID로 만들었다.
또한 사라진 임시 검출이 2초간 남아 다른 카메라의 첫 사람을 먼저 차지할 수 있었다.
한 카메라에서 이미 연결한 ID에 대해 다른 카메라의 좌표로 다시 연결하는 경로도 있었다.
번호를 압축해도 잘못 나뉜 내부 ID는 합쳐지지 않아 같은 사람이 person1, person2로 갈라졌다.
이 경우 DANGER/SAFE가 한 행에서 SAFE로 결합되는 대신 DANGER/UNKNOWN과 UNKNOWN/SAFE 두 행으로 분리됐다.

실행 로그 `20261031T150825+0900_f1870cad`에서는 CAM2 frame 157에 같은 발 위치의
전체 박스와 작은 박스가 함께 검출됐다. 이중 검출도 서로 다른 ID를 생성하고 이후 추적을 나누는 원인이었다.

## 변경한 규칙

1. 같은 카메라의 기존 사람부터 해당 카메라의 좌표·영상 기준점·이동 예측으로 일대일 추적한다.
2. 새 사람은 다른 카메라에서 현재 보이는 미연결 사람의 등장 순서로 연결한다.
   XY가 다르다는 이유만으로 이 순차 연결을 거부하지 않는다.
3. 현재 보이는 사람이 사라진 임시 ID보다 우선한다. 다른 카메라도 잠깐 미검출이면
   2초 이내 최근 관측된 미연결 사람부터 재연결한다.
4. 여러 사람이 한 프레임에 처음 등장하면 시간 순서가 없으므로 공통 Ground 근접도를 보조 기준으로 사용한다.
5. 연결된 내부 `track_id` 아래 CAM1과 CAM2의 좌표·속도를 따로 저장한다.
   다른 카메라의 좌표로 이미 등록한 카메라의 ID를 덮어쓰지 않는다.
   한쪽이 계속 추적 중이면 반대쪽의 마지막 위치도 보관한다.
6. 표시 번호만 현재 사람들의 순서대로 압축한다. 내부 ID, 카메라 연결, 현재 SAFE/DANGER는 그대로 유지한다.
   예: 내부 person8/person10 → 표시 person1/person2. 후속 수정에서는 카메라별 영상 매핑과 공통 결합 행 매핑을 구분한다.
7. 추적 전 Person 중복 박스를 정리한다. IoU 0.7 이상인 박스 또는 크기가 비슷하고
   발 위치가 거의 일치하는 포함 박스는 높은 신뢰도 하나를 남긴다. 훨씬 큰 박스가 작은 사람을 포함한다는 이유만으로 지우지 않는다.

기존 SAFE/DANGER/UNKNOWN 결합표, UNKNOWN/UNKNOWN 행 숨김, 위험 LATCH 및 SITE SAFE 확인 후 RESET 정책은 유지한다.
현재 표가 SAFE가 되어도 기존 위험 LATCH는 관리자 RESET 전까지 최종 DANGER로 남는다.
